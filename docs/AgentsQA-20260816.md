**这是根因，不是因为它复杂，而是因为它定义了"模型在什么流形上输出"**。`tax3d_v2.py` 一旦把 contract 猜偏，训练 loss 仍然会下降（网络在拟合某种东西），但推理时消费的是错的流形。后面所有的「训练 loss 正常、simulator 不 work」症状都从这里出。

### 2. frame_type + pred_frame + zero_shape 的静默契约

当前 checkpoint 的配置是 `frame_type=fixed / pred_frame=noisy_goal / zero_shape=true`【4】。这三个 flag 共同决定了一个**不在代码注释里、也不在论文正文里**的契约：

- `frame_type=fixed` → 选 `TAX3Dv2FixedFrameModule`（缺失）
- `pred_frame=noisy_goal` → dataset 在 batch 里塞一个 `noisy_goal` 字段当作 frame 监督
- `zero_shape=true` → shape head 只预测零均值形状（ϕ_0 mean-centered）

你 8 月 13 日的 issue follow-up 已经指出："fixed-frame module does not directly use `batch['noisy_goal']`, while the dataset does create this field when `pred_frame=noisy_goal`【2】."

**这是「静默」的**：任何一个 flag 解释错，loss 仍然下降、checkpoint 仍然能 load，但模型在学的东西和 inference 时需要它输出的东西**不在同一个流形上**。51° 的旋转误差和 28.6% 的成功率都直接源自这里。

### 3. GMM 脱钩的次因地位

`gmm_predictor.py`（14.4 KB，定义了 `FrameGMMPredictor`）和 `train_gmm.py` 在公开仓库里都存在【3】【4】。也就是说，GMM 的核心代码并不缺失。

但当前 inference 完全没用 GMM checkpoint。论文 Table I 给出的上限是：w/o GMM = 74%【5】。做一个简单算术：假设 GMM 完美兑现论文里的 21 个百分点，28.6% + 21 = 49.6%，**仍远低于 paper w/o-GMM 的 74% 基准**。

这意味着：**就算明天把 GMM 跑通接入 inference，这个 gap 也填不平**。GMM 是一个真实但非主导的因素，把它当成根因会误导排障顺序。

### 4. RANSAC 缺位的边际作用

论文 Appendix III-E 提到 RANSAC + SVD，但没给迭代数 N 和内点阈值 τ【5】。当前用 plain SVD。

RANSAC 的作用是**在 inlier 多数 / outlier 少数**的预测里挑出刚体约束。`R_err_WTA = 51.38°` 意味着预测本身就是错的，RANSAC 选不出能拟合这种散点的 rigid transform——**RANSAC 是 outlier 抵抗器，不是 51° 修正器**。它能贡献的只是几个百分点，不是主因。

### 5. 任务命名 / 数据 split 的不可消除噪声

RPDiff 官方可下载数据 `mug_on_rack_multi_large_proc_gen_demos`，作者自己的脚本把它标为 `Mug_Rack_Hard_Multi`【4】，**不是论文 Table I 里的 `Mug/Multi-MedRack`【5】**。这层数据身份的不一致是不可控的——可能作者用的是未公开的私有 split。

保守估计 5–10 个百分点的不可消除噪声归在这里。它不能解释 66 个百分点的差距，但叠加到前 4 条因上，每个都会让问题更难看。

### 6. 28.6% 数字的仓外来源

你这份复现记录里 28.6% 的 500-trial 结果，是仓外 patch `/home/yuchi/projects/rpdiff` 里的 `tax_dpd_external` adapter 跑出来的【4】，**当前 TAX-DPD 仓库里没有这块代码**。这意味着：

- 当前仓库无法"重放" 28.6% 这个数字本身；
- 后续任何对 `tax3d_v2.py` 的修改都不会反映到 28.6% 上；
- 复现记录不能视为"来自这个仓库"的报告。

这是方法学层面的问题，不是算法问题。

## 三、非显然的判断

**「复现失败」与「重构上界」是两个不同的概念**。当前 28.6% 是一个 best-effort 重构在不可控 adapter 上的输出，**不能直接和 paper 的 95% 同协议比较**。把它表述成"复现失败"是范畴混淆，更准确的说法是"重构上界"——其上限取决于缺失 contract 部分的真实结构。

**51° R_err_WTA 是真正的近端症状**。所有上层因素最终都汇流到这里：如果 rotation error 降不下来，hanging task 的物理成功率就是几何期望的低值。所以**修任何东西时，看 R_err_WTA 是否在降**比看 simulator success 升降更可靠。simulator success 还会被接触判定、controller 容差等下游因素干扰，R_err_WTA 是直接来自模型输出的指标。

**诊断 ablation 已经基本排除了一些常见嫌疑**。100/500-trial 主实验之外跑的 4 个 ablation：random init → 38%、init_orig_ori + init_parent_mean_pos → 24%、identity rotation → 26.7%、inverse-SVD sanity check → 26.7%【4】。这四个结果都在 24–38% 之间，**说明问题不是「初始化错了」「SVD 方向反了」「不用旋转」这种单一可定位的 bug**。换句话说，常规 transform 修正路径已经走不通了，剩下的就是 contract 级的问题。

**仓库本身处于"实质性冻结"状态**。最后一次 commit 是 2026-06-22，距 issue 提交近两个月。README 的 Roadmap 里 installation / training / evaluation / pre-trained checkpoints 四个 checkbox 全是空的【6】。这个 issue 短期内不会得到官方修复——复现工作必须在"官方不修"的前提下做决策。

## 四、可修与不可消除的边界

把上面 6 条因中 4 条可修的、2 条不可消除的、1 条可补的整理成下表：

| 类别 | 具体问题 | 修法成本 | 期望收益 |
|---|---|---|---|
| 可修 | `tax3d_v2.py` 的 fixed-frame 合约 | 高（必须从论文 + 项目页 MP4 + 逆向工程反推） | 主因被消掉，R_err_WTA 可能大幅下降 |
| 可修 | `pred_frame / zero_shape` 的合约一致性 | 中 | 让训练 loss 的含义回到 paper 描述的分布上 |
| 可修 | GMM 接入 inference 路径 | 中 | +5–10 pp 期望 |
| 可修 | RANSAC 接入 | 低 | 边际收益（inlier 多数时有效，当前不是这种情况） |
| 不可消除 | 数据 split 身份与 paper 不完全一致 | 不可 | 5–10 pp 噪声 |
| 不可消除 | RPDiff controller / 仿真参数与 paper 是否完全一致 | 不可 | 不可估计 |
| 可补 | adapter 在仓外 | 中（可提 PR 把 patch 提交进 repo） | 解决可复现性，不解决性能 |

表里 4 条「可修」之间的收益不是独立的——前 3 条都建立在第 1 条（fixed-frame 合约）已经修好的前提下；根因没消掉，后 3 条的边际收益会显著缩水。两条「不可消除」是协议层面的硬上限，无论怎么调仓内代码都打不破。可补的 adapter 项不进入性能分母，但能让后续的实验可重放。

## 五、核心判断

28.6% 与 95% 的差距，本质上是**一个 contract-reconstruction gap**，不是 hyperparameter gap / data gap / RPDiff tuning gap。`tax3d_v2.py` 的 fixed-frame 合约没有公开参考实现这件事没修好之前，往上加 GMM、改 RANSAC、调 RPDiff 配置都不会真正关上这条 gap。最有杠杆的下一步不是再多跑 trial 或多训 epoch，而是**回到 `tax3d_v2.py` 的 forward 合约本身**——把 `frame_type=fixed` 在 `TAX3Dv2FixedFrameModule` 里的 `noisy_goal` 消费方式、`zero_shape=true` 下的 shape head 输出定义、`ρ` / `ϕ` 的 noise schedule 对齐，逐项与论文 Eq. 2-4 / Sec. IV-B 核对清楚。

## 4. Offline eval：`_predict_wta` + RMSE/SE(3) 误差

跑 `scripts/eval_rigid.py`，**不连接 PyBullet，不推进 simulator**。流程是：
1. 加载 checkpoint
2. 加载 RPDiff test dataset（400 个样本）
3. 对每个样本调用 `_predict_wta`：
   - 采样 K=10 个候选预测
   - 对每个预测拟合 SE(3) (用 SVD)
   - 选**离 GT 最近的**那一个（这是 WTA 的关键——**WTA 用了 GT 选择**，不是部署接口）
4. 统计 RMSE / T_err / R_err

**注意**：WTA 用 GT 选择是 offline 评估技巧，**不能用于部署**。但它衡量的是"模型的最佳潜在能力"——如果 WTA 都差，说明模型本身不够好；如果 WTA 好但 one-shot 差，说明需要多次采样。

得到的数字（**注意单位**：长度是相对单位，rotation 是度）：

```
Val  T_err: 0.25   T_err_WTA: 0.13
Val  R_err: 122.7° R_err_WTA: 55.2°
Test RMSE: 0.29   RMSE_WTA: 0.16
Test T_err: 0.25   T_err_WTA: 0.12
Test R_err: 121.0° R_err_WTA: 51.4°
```

`R_err_WTA=51°` 这个数字非常关键——**它就是 28.6% simulator success 的直接来源**。一个 51° 旋转误差的 mug 不可能挂到 rack 上。

## 5. Simulator eval：仓外 `tax_dpd_external` 适配器

这是**最容易误解的部分**。28.6% 这个数字不是在 TAX-DPD 仓内跑出来的，而是在 RPDiff 仓内用 adapter 跑出来的。

适配器代码在 `/home/yuchi/projects/rpdiff/src/rpdiff/eval/evaluate_rpdiff.py`，主要工作流：

```python
# 对每个 trial:
1. 加载 RPDiff task config 和场景
2. 采样 parent (rack) 和 child (mug) 的点云
3. 调用 TAX-DPD._predict_wta 得到预测的目标点云
4. 用 SVD 把 child 的初始点云配准到预测点云 → SE(3)
5. 把 SE(3) 喂给 RPDiff 的 insertion controller
6. RPDiff controller 在 PyBullet 里执行
7. 仿真结束后检查 Place Success 和 touching_surf
```

**关键 RPDiff 配置文件**（在 rpdiff 仓内）：
- `mug_on_rack_multi_tax_dpd_smoke.yaml` (5 trials)
- `mug_on_rack_multi_tax_dpd_100.yaml`
- `mug_on_rack_multi_tax_dpd_500.yaml`
- `mug_on_rack_multi_tax_dpd_diag50.yaml` (random init)
- `mug_on_rack_multi_tax_dpd_init_diag50.yaml` (init_orig_ori + init_parent_mean_pos)
- `mug_on_rack_multi_tax_dpd_identityrot30.yaml` (只取预测点云的中心，不做 SVD 旋转)

- **A4 — Schedule contract**: ϕ and ρ share the same noise schedule {ᾱ_t}. If they're desynchronized, the denoising chain breaks.
- **A5 — Embedding contracts**: Three PointNet++ encoders take three different inputs — (ˆg P_S, ˆg ˆP*_{O,t}) for reconstruction, ˆO P_O (in **world frame**!) for object, and ˆϕ_t - ˆO P_O for deformation. These three streams feed into the dual-head denoiser.

- **A7 — Composition contract**: At each denoising step, the input to the model is ˆg ˆP*_{O,t} = ϕ̂_t + ρ̂_t. This recursive form must hold.
- **A8 — World restoration contract**: P*_O = ˆg ˆP*_O + ˆg. **Translation only, no rotation.** The ˆg frame is parallel to world, just translated.
- **A9 — Correspondence contract**: Each input object point has a 1-to-1 correspondence to a predicted target point. For rigid: derived from kinematics. RANSAC-SVD uses this.

- **A13 — Training-time ˆg contract**: For f_local training, ˆg_train ~ N(P*_O, Σ=I), not sampled from f_global. This avoids mode-mismatch.
- **A14 — Rigid compatibility contract**: For rigid objects, the predicted point cloud must be internally rigid-consistent. RANSAC-SVD enforces this; without it, predictions are not projectable to SE(3).

## 2. Precise concept disambiguation

- **Contract** (in this domain): the **implicit agreement** between two modules about the meaning/format/coordinate of the data they pass. Not documented in the paper, must be inferred from the equations and the design.
- **Manifold** (in this domain): the **mathematical space** on which the data lives. Locally Euclidean; may have additional structure (affine subspace, group action, metric).
- **Affine subspace** vs **subspace**: A subspace contains 0; an affine subspace is shifted by a constant. M_ϕ = {x : mean(x) = 0} is a subspace (it contains 0).
- **SE(3) vs R^(N×3)**: SE(3) is 6-dimensional (3 rotation + 3 translation). R^(N×3) is 3N-dimensional (free point cloud). RANSAC-SVD projects from R^(3N) to SE(3) by rigid-consistency.
- **Translation only** vs **full SE(3) frame**: ˆg is just a 3D point; the ˆg frame has the same orientation as the world frame. This is a **deliberate simplification**, not a missing rotation.
- **Mean-centered shape ϕ**: ϕ has mean zero, so it can be summed with ρ (3D vector, broadcast) to get a point cloud with a specific centroid. Without the mean-zero constraint, ϕ + ρ would double-count or miss the centroid.
- **Per-point iid noise** vs **per-vector iid noise**: ϕ noise is N_O × 3 matrix with iid entries; ρ noise is 3-vector with iid entries. Both are iid, but at different "granularities".
- **Rotation noise ε_rot = Rϕ_0 - ϕ_0**: This is NOT a Gaussian noise — it's a rigid rotation of the entire point cloud. It introduces per-point correlation that the model must learn to handle.
- **Discrete GMM sampling** vs **continuous mixture sampling**: The paper specifies categorical sampling, which gives a discrete ˆg. Continuous mixture would give a weighted average that may not be a valid placement.
- **"Object frame" in the paper** vs **SE(3) frame**: The paper uses "frame" loosely. In the disentanglement, "frame" means **the centroid position** (3D point), not a full SE(3) reference frame.

# TAX-DPD 复现补全的 contracts 与输出流形

## 一、模型输出所在流形的数学结构

把推理流程跑完 100 步去噪之后，模型的输出是一个二元组 $(\hat{\phi}_0, \hat{\rho}_0) \in \mathbb{R}^{N_O \times 3} \times \mathbb{R}^3$。但 $\hat{\phi}_0$ 不是自由点云——它**必须满足** `mean($\hat{\phi}_0$) = 0`（沿 $N_O$ 个点取均值）。这是一个仿射约束：$\hat{\phi}_0$ 实际上位于 $M_\phi := \{x \in \mathbb{R}^{N_O \times 3} : \text{mean}(x) = 0\}$ 里，这是一个 $(3N_O - 3)$ 维的线性子空间（包含原点，所以是子空间不是仿射子空间）。$\hat{\rho}_0$ 没有这个约束，处在普通 $\mathbb{R}^3$ 里。

完整的输出流形是 $M_\phi \times \mathbb{R}^3$，总维度 $(3N_O - 3) + 3 = 3N_O$。这个数字看起来很大，但跟"一个 $N_O$ 点的自由点云"的 $3N_O$ 个 DOF 是一样的——`mean = 0` 把 DOF 减了 3，但 $\rho$ 又把这 3 个补回来。**所以 $(\phi, \rho)$ 分解并没有引入冗余 DOF，它只是把同一个 $3N_O$ 维空间重新参数化**。

经过 RANSAC-SVD 投影之后，模型输出被进一步压缩到 $\text{SE}(3)$ 的 6 个 DOF。这是**第二个层级的流形约束**，从过参数化点云到刚体变换。整条 pipeline 的流形结构是：

```
M_ϕ × R³     (model output, 3N_O DOF)
   ↓  rigid projection (RANSAC-SVD)
SE(3)         (final transform, 6 DOF)
```

"任何 contract 错位都会让模型输出在错的流形上" 这句话的精确含义是：每一个 contract 都是输出流形上的一条约束，错一条 = 输出被推出正确的 $M_\phi \times \mathbb{R}^3$ 子集，或者被推出正确的分布。下面把每个 contract 在哪个位置起作用、错位后输出会落到哪里一一拆开。

## 二、按 pipeline 阶段展开的 contracts

### 1. 帧平移 contract

ˆg ∈ R³ 是一个**纯平移点**，不是 SE(3) frame。ˆg frame 跟 world frame 共享同一组基向量，**只是位置被平移了 ˆg**。所有 "ˆg P" 形式的输入都表示「把点云 $P$ 平移 $-ˆg$」，不是旋转。这个 contract 让 ˆg frame 是 world frame 的"平移副本"——ϕ₀ 的旋转自由度（3 DOF）和 ρ₀ 的平移自由度（3 DOF）都是相对于 world frame 测量的。

如果 wrapper 把 ˆg 当作 SE(3) frame（即 `ˆg ˆP* = R · ˆP* + ˆg`），输出点云会被世界系下的旋转扭曲，RANSAC-SVD 拿到的 SE(3) 旋转会把这个错位放大。51° 旋转误差最可能的来源之一就在这里。

### 2. 分解 contract（$\phi + \rho = \widehat{g}\widehat{P}^*$）

论文 Eq. 2 把 $\widehat{g}\widehat{P}^*_O$ 唯一地分解成 mean-centered 形状 $\phi_0$ 和 centroid 偏移 $\rho_0$：$\widehat{g}\widehat{P}^*_O = \phi_0 + \rho_0$（$\rho_0 \in \mathbb{R}^3$ 被广播到 $N_O$ 个点）。这个等式**不是任意的**——它把 $\widehat{g}\widehat{P}^*_O$ 唯一的"中心"信息（3 DOF）剥离到 $\rho_0$，把剩下的"形状"信息（$3N_O - 3$ DOF）留给 $\phi_0$。$\phi_0$ 的 mean-zero 约束是这个分解的**自然结果**，不是附加条件。

如果 wrapper 让 $\phi_0$ 有非零均值，那么 $\phi_0 + \rho_0$ 的质心会变成 `mean($\phi_0$) + $\rho_0$` 而非 $\rho_0$——**双计数**了。当前实现里 `T_action2goal` 是单位阵（不携带真实的物体放置变换），正是这种 double-count 风险的具体表现。

### 3. 噪声结构 contract

论文 Eq. 3-4 对 $\phi$ 和 $\rho$ 施加了**结构不同**的噪声：$\phi_t = \sqrt{\bar\alpha_t}\,\phi_0 + \sqrt{1-\bar\alpha_t}\,\epsilon_\phi$，$\epsilon_\phi \sim \mathcal{N}(0, I) \in \mathbb{R}^{N_O \times 3}$ 是**逐点独立**的；$\rho_t$ 的 $\epsilon_\rho \sim \mathcal{N}(0, I) \in \mathbb{R}^3$ 是**3 维独立**的。$\phi$ 的逐点独立编码了"点云是无序集合"的假设——这正是 PointNet++ 能用的原因；$\rho$ 的 3 维独立编码了 $\rho$ 不承载形状信息的假设。

如果 wrapper 用 per-vertex 相关噪声（即 $\phi$ 的噪声矩阵不是 iid 的），PointNet++ 的置换不变性就破了，模型学到的形状分布会偏离正确流形。

### 4. 旋转噪声 contract

Sec. IV-B 在 $\phi$ 的 forward 过程里注入了额外的**刚体旋转**噪声：$\epsilon_{\text{rot}} = R\phi_0 - \phi_0$，其中 $u \sim U(S^2)$，$\theta \sim \mathcal{N}(0, (\pi/4)^2)$，$R$ 由罗德里格公式构造。$\phi$ 的 forward 过程变成 $\phi_t = \sqrt{\bar\alpha_t}\,\phi_0 + \sqrt{1-\bar\alpha_t}\,(\epsilon_\phi + \epsilon_{\text{rot}})$。**注意：$\epsilon_{\text{rot}}$ 只在 $\phi$ 上加，不在 $\rho$ 上加**。

这是**最被低估**的一条 contract。$\epsilon_{\text{rot}}$ 引入的不是"随机噪声"——是**整片点云的刚体旋转**。它把所有点耦合在同一条相关结构里：所有 $N_O$ 个点共享同一个 $R$。**没有 $\epsilon_{\text{rot}}$，模型无法学到 $\phi$ 空间的"刚体结构"**——也就是说，模型不会知道"对一个刚体，所有点应该一起转"。

更精确地说：$\epsilon_{\text{rot}}$ 把 $\phi$ 的训练分布**限制在 $M_\phi$ 中"刚体可旋转"的那个子流形**上。论文的 ablation 表明，去掉 rotation noise，Mug 任务掉 17 个百分点——**这是非显然的因果链**：rotation noise 决定了 $\phi$ 流形上有意义的区域。

### 5. Schedule 共享 contract

$\phi$ 和 $\rho$ 使用**同一套** noise schedule $\{\bar\alpha_t\}$。去噪链是同步的：$t$ 时刻的 `ˆg ˆP*_{O,t} = $\hat{\phi}_t + \hat{\rho}_t$` 必须跟下一步 `$\hat{\phi}_{t-1} + \hat{\rho}_{t-1}$` 的"年龄"匹配。Schedule 错位会让反向过程跨步——ϕ 和 ρ 在不同"年龄"上做 composition 时会出现非物理合成。

### 6. 三路 embedding contract

Sec. IV-B 描述了三个 PointNet++ 编码器，**输入各不相同**：reconstruction 编码 `(ˆg P_S, ˆg ˆP*_{O,t})`（场景 + 当前去噪物体，**用同一个编码器**学"物体在场景里应该长啥样"）；object 编码 `ˆO P_O = P_O - mean(P_O)`（**world frame 下的初始物体**，mean-centered）；deformation 编码 `$\hat{\phi}_t - ˆO P_O$`（当前去噪形状与初始形状的逐点位移，**两者都 mean-centered**，所以差也是 mean-centered，专门编码"刚体旋转"或"形变"）。

注意**不对称**：reconstruction 在 ˆg frame，object 在 world frame。这种不对称是 intentional 的——模型需要"原始物体形状"（world frame 下的）来推理形变，但不能把它放在 ˆg frame（否则 object 跟 reconstruction 错位）。如果 wrapper 把 object embedding 改成在 ˆg frame 下做，shape head 拿到的"原始形状"就跟 reconstruction 错位，disentanglement 学不到。

### 7. World 恢复 contract

Sec. IV-B 给出 $P^*_O = \widehat{g}\widehat{P}^*_O + \widehat{g}$，**纯平移**，没有旋转。这是从 $M_\phi \times \mathbb{R}^3$（ˆg frame）回到 world frame 的"最后一公里"——同一个仿射变换在不同坐标系下的表达。如果 wrapper 在这一步加了旋转（例如 `R · ˆg ˆP*_O + ˆg`），世界系下的输出会被旋转，RANSAC-SVD 拿到的 SE(3) 旋转会把错位放大。

### 8. RANSAC-SVD 投影 contract

Sec. IV item 3：从 predicted point cloud 的 $N_O$ 对逐点对应关系，RANSAC 选最大 inlier 子集，SVD 拟合 SE(3)。**这是过参数化流形 $M_\phi \times \mathbb{R}^3$ 到目标流形 $\text{SE}(3)$ 的投影**：$3N_O$ DOF → 6 DOF。RANSAC 处理 per-point 预测误差，SVD 给最优刚体拟合。

这条 contract 是过参数化处理，**不是**其他 11 条 contract 那种"分布约束"——它是**流形投影**。Plain SVD（不用 RANSAC）会让 per-point 误差污染旋转矩阵。51° 旋转误差的部分来源是这一步——per-point 预测已经偏离了 6 DOF manifold 的"合规形状"，plain SVD 把这种偏离当成 inlier 拟合。

### 9. GMM 采样 contract

Sec. IV-A 给出 $\widehat{g} \sim f_{\text{global}}(P_O, P_S)$ 走**分类采样**——先按 mixing weight $\{w_i\}$ 选分量 $i$，然后取 $p_i + r_i$ 作为 $\widehat{g}$。**不是**连续加权平均。$\widehat{g}$ 的取值空间是离散集 $\{p_i + r_i : i \in [1, N_S]\}$，是从场景点云里**挑**一个位置。如果 wrapper 把分类采样改成连续混合（按 $w_i$ 加权平均 $p_i + r_i$），$\widehat{g}$ 会落在所有 mode 之间的"几何平均"位置——多模态性被熨平，下游 DPD 在错误的 $\widehat{g}$ frame 里精修。

### 10. 训练-推理 $\widehat{g}$ 分布 contract

Sec. IV-C 说明 $f_{\text{local}}$ 训练时 $\widehat{g}_{\text{train}} \sim \mathcal{N}(\overline{P^*_O}, \Sigma=I)$，**不**从 $f_{\text{global}}$ 采样。推理时才用 $f_{\text{global}}$。两者分布不同，但**训练用的扰动尺度 $\Sigma = I$ 与推理时 $f_{\text{global}}$ 误差量级匹配**——这是论文没明说但要保证的隐式 contract。如果 $\Sigma$ 设得太大，训练时 $\phi$ 头部被强制做大范围去噪；推理时 $f_{\text{global}}$ 误差小得多，模型反而"过度去噪"，输出被推回原点。

### 11. Correspondence contract

Sec. IV item 3 隐含：每个输入点 $p_i$ 与 predicted point $\hat{p}^*_i$ 维持**逐点对应**（rigid 时来自 kinematics），RANSAC-SVD 依赖这层对应。把"过参数化点云"压回 SE(3) 时，对应关系提供了**等距约束**——所有 $N_O$ 对的 $(p_i, \hat{p}^*_i)$ 必须满足同一个刚体变换。这条 contract 让 RANSAC 的"3 对应点估 SE(3)"成为可能。

如果 wrapper 在 SVD 之前对 predicted cloud 做了 FPS 下采样或排序打乱，对应关系就丢了，RANSAC 选出来的 inlier 不再是"同一个 $R$ 的体现"，拟合出的 SE(3) 是噪声平均。

### 12. DiT 结构性 contract

Sec. IV-C 给出 5 blocks / 4 heads / hidden 128 的 modified DiT；object tokens 和 frame token 与 scene tokens 交叉注意力；frame token 解码到 $\hat{\rho}_t$，object tokens 解码到 $\hat{\phi}_t$。Dual-head 不是架构偏好——**是流形分解的实现**。$\phi$ 和 $\rho$ 的流形结构不同（一个是 mean-zero 子空间，一个是 $\mathbb{R}^3$），单一 head 没法在共享参数下高效学两个不同流形的分布。dual-head 把流形分解烧进前向图。

## 三、几个非显然但关键的判断

$(\phi, \rho)$ 分解不是 over-parameterization，是 reparametrization。总 DOF 是 $3N_O$（$\phi$ 给 $3N_O-3$，$\rho$ 给 3，加起来 $3N_O$），跟"自由点云"一样多。"过参数化"只发生在从 $3N_O$ DOF 压缩到 SE(3) 6 DOF 的那一步——RANSAC-SVD 才是真正的过参数化处理。

旋转噪声 $\epsilon_{\text{rot}}$ 是 $\phi$ manifold 的"塑形器"。它把 $M_\phi$ 进一步限制到"刚体可旋转"子流形 $M_\phi^{(\text{rigid})} \subset M_\phi$ 上。没有它，模型学到的形状分布是"任意点云"，加上它才学到"刚体可旋转的形状"——这是 paper ablation 里 R_err 显著恶化的根因。

dual-head 不是架构偏好，是流形分解的实现。$\phi$ 和 $\rho$ 的流形结构不同（一个是 mean-zero 子空间，一个是 $\mathbb{R}^3$），单一 head 没法在共享参数下高效学两个不同流形的分布。dual-head 把流形分解烧进前向图。

World 恢复的"纯平移"是把流形恢复的关键。$\widehat{g}$ frame 是 world frame 的平移副本（保留 X/Y/Z 朝向），所以从 $\widehat{g}$ frame 回到 world frame 是**纯平移**，不需要处理旋转。`T_action2goal` 在当前实现里是单位阵——这暗示有人**忘了在 $\widehat{g}$ frame 下做**——是世界恢复层最可能的错位源。

51° 旋转误差的来源分布在多个 contract 上，不是单点 bug。最大头是**流形错位**（contract 1, 2, 6 任一错位）——per-point 预测在被推出正确 manifold；次头是**过参数化投影的精度**（contract 8 plain SVD 没用 RANSAC）——inlier 比例低时 RANSAC 才有意义。两者叠加，所以 random init 反而能 38%。

## 四、给复现补全的具体含义

| 优先级 | 要补的 contract | 验证方式 |
|---|---|---|
| P1 | $\phi$ 的 mean-zero 约束（contract 2） | 任意样本上 check `mean($\hat{\phi}_0$) == 0`；不通过则 wrapper 错位 |

| P2 | world 恢复是纯平移（contract 7） | check $P^*_O - (\widehat{g}\widehat{P}^*_O + \widehat{g}) == 0$；不通过则有人加了旋转 |

表里 P1 三条都是先验约束（model 在正确流形上学），P2 三条是流形恢复层的合约，P3 三条是过参数化投影和采样策略。P1 没修完之前，P3 里的 RANSAC 不会起决定性作用——把 $\phi$ 推出正确 manifold 之后，RANSAC 才有意义。
